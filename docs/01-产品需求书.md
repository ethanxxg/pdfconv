## 1. 概述

### 1.1 背景与目标

业务系统需要在服务器和桌面程序里创建、修改、转换、渲染办公文档。依赖本机安装的 Microsoft Office 或 Adobe Acrobat 会带来进程自动化不稳定、无界面服务器无法部署、并发许可昂贵、Linux 不可用等问题。

Aspose.Total for C++ 把字处理、表格、PDF、演示文稿、邮件、条码、OCR 等能力做成不启动 Office 的本地库。DocCore 的目标是做出一套**独立实现**的同类软件：以 C++ 库为主交付物，附带命令行工具和可选本地 HTTP 服务，让宿主程序在不安装 Office/Acrobat 的前提下完成同类文档任务。

实现依据是公开文件格式规范与自研引擎，包括 ISO/IEC 29500（OOXML）、ECMA-376、ISO 32000（PDF）、MS-CFB、MIME（RFC 2045 及后续）等。产品命名、公开 API、源码均独立，不使用 Aspose 商标，不复制其专有实现。模块与命名空间使用中性词（`text`、`sheet`、`pdf`、`deck`），不使用与对标产品模块同构的命名（如 `words`、`cells`、`slides`），公开类型名也不沿用其专有拼写。

**目标用户**

- 把文档能力嵌进业务系统的后端与桌面开发者
- 需要批量转换、套打、报表导出的服务端团队
- 需要在 Windows 与 Linux 上用同一套库的交付团队

**成功指标**

| 指标 | 目标 | 度量方式 |
|------|------|----------|
| 无 Office 依赖 | 运行期零 Office/Acrobat 进程 | 集成测试环境不安装 Office |
| 平台 | Windows x64 与 Linux x64 同源 API | 同一测试集双平台通过 |
| 字处理结构保真 | P0 黄金样本集结构检查通过率 ≥ 95% | 段落、表格、样式、节属性对比 |
| 中文版式 | A4 公文类样本 PDF 文本层与分页一致 | 文本抽取 + 页数 + 关键坐标容差 |
| 办公文档与 PDF 互转 | DOCX、XLSX、PPTX 与 PDF 六个方向都可转换 | 见 F-310、F-311、F-312 的黄金样本 |
| 表格计算 | P0 公式集结果与 Excel 兼容实现一致 | 公式黄金集，容差按数值类型定义 |
| 打开性能 | 10 MB、约 200 页纯文本 DOCX 冷启动打开 < 1.5 s | 基准机：8 核、32 GB、SSD |
| 大表 | 50 MB XLSX（约 50 万单元格）打开 < 5 s，峰值内存 < 解压后文本的 4 倍 | 同上 |
| 安全基线 | 拒绝压缩炸弹、XML 实体扩展、宏执行、默认外联 | 恶意样本集全部被拒绝或隔离 |
| 许可清晰 | 每个第三方组件的许可证可随发行包声明 | 第三方清单随版本发布 |

### 1.2 术语定义

| 术语 | 定义 |
|------|------|
| 宿主 | 链接 DocCore 或调用其 CLI/HTTP 的业务程序 |
| 文档族 | 同一文档模型下的格式集合，例如字处理族、表格族、演示族、页面族 |
| DOM | 某文档族在内存中的可编辑对象树 |
| 版式中间表示（Layout IR） | 分页后的绘制指令：页、文字字形、路径、图像、链接。固定版式输出的公共输入 |
| 转换总线 | 按“源解码器 → 文档模型或 Layout IR → 目标编码器”调度的转换层 |
| 套打 | 用数据记录填充模板中的合并域或单元格占位，批量生成文档 |
| 结构保真 | 往返后语义对象仍在：样式、段落、表格结构、公式文本、幻灯片形状树。不要求 XML 字节级一致 |
| 视觉回归 | 把渲染结果光栅化后与基准图比较 |
| 黄金样本 | 纳入持续集成、有明确期望结果的文档与用例 |
| P0–P3 | 见第 3 节优先级定义 |

### 1.3 产品形态

DocCore 是一套软件，不是单一可执行文件。

| 形态 | 使用者 | 说明 |
|------|--------|------|
| C++ SDK | 集成开发者 | 主交付物。头文件、静态库或动态库、CMake 包 |
| C ABI | 其他语言绑定 | 稳定的 C 接口，供 Python、C#、Java、Rust 绑定 |
| `doccore` CLI | 运维与批处理 | 探测格式、转换、套打、抽取文本、计算工作簿 |
| 本地 HTTP 服务 | 不便链接原生库的系统 | 可选进程。上传、转换、下载。默认只监听本机 |

浏览器里的完整 Office 编辑器不在本产品范围内。

### 1.4 范围

**在范围内**

- 离线创建、读取、修改、保存、转换、渲染下列文档族
- 字处理、电子表格、PDF、演示文稿为第一阶段主体
- PDF 与 DOCX、XLSX、PPTX 双向转换：办公文档导出版式保真的 PDF，PDF 再重建为可编辑的 Word、Excel、PPT
- 邮件、条码、字体工具为第二阶段
- OCR、XPS/PS/EPS、项目计划、TeX、Publisher、光标阅读为后续阶段
- 文档加密文件的打开与保存（调用方提供密码）
- 宏的保留与删除；默认不执行宏

**不在范围内**

- 替代 Office 的交互式排版界面
- 充当邮件服务器、打印后台或扫描设备驱动
- 执行 VBA、JavaScript 宏、PDF JavaScript
- 破解或绕过第三方软件许可
- 保证与某闭源产品的未公开行为逐字节一致
- 实时多人协同编辑

## 2. 用户角色

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 集成开发者 | 在服务或桌面程序中调用 SDK | API 稳定、无 Office、错误可诊断、文档可预期 |
| 批处理作业方 | 用 CLI 或 HTTP 做夜间转换与套打 | 可脚本化、失败可重试、单文件失败不拖垮批次 |
| 模板设计方 | 在 Office 中做好模板，交给系统填充 | 合并域、内容控件、命名区域被正确识别 |

| 测试工程师 | 维护黄金样本与视觉回归 | 失败能定位到格式、页、对象 |
| 许可管理员 | 管理 DocCore 自身的发行许可 | 离线激活、到期行为明确、不上传客户文档 |

### 3.2 用户故事与验收标准

#### F-001: 格式探测与统一打开/保存入口

**用户故事：** 作为集成开发者，我希望用同一入口打开路径、字节或流，并在保存时按目标格式写出，以便业务代码不必先判断文件种类。

**验收标准：**

- [ ] Given 扩展名缺失或被改错的 DOCX，When 探测，Then 依据 ZIP 包内 `[Content_Types].xml` 识别为字处理 OOXML，而不是仅凭扩展名。
- [ ] Given 加密的 OOXML，When 未提供密码，Then 返回“需要密码”，且不把文件内容写入日志。
- [ ] Given 无法识别的字节，When 打开，Then 返回“格式不支持”，进程不崩溃。

**业务规则：**

- 探测顺序为：容器签名（ZIP、CFB、PDF、MIME）优先于扩展名。
- 同一文件允许显式指定格式，显式格式与内容冲突时返回错误，不静默另选格式。

#### F-002: 文件、内存与流 IO

**用户故事：** 作为服务端开发者，我希望从内存字节打开并保存到内存，以便临时文件不落盘。

**验收标准：**

- [ ] Given 完整 DOCX 字节数组，When 打开并另存为字节数组，Then 产物可再次打开且正文与原文档一致。
- [ ] Given 调用方提前关闭的流，When 读取未完成，Then 返回 IO 错误并释放已分配的文档对象。

#### F-004: 统一错误、警告与取消

**用户故事：** 作为集成开发者，我希望可恢复问题以警告返回、致命问题以错误返回，并能取消长时间排版，以便服务能设置时限。

**验收标准：**

- [ ] Given 含不受支持字段的文档，When 打开，Then 文档仍可用，并产生至少一条带源位置的警告。
- [ ] Given 排版过程中调用取消，When 取消被接受，Then 在当前页结束后停止，返回“已取消”，不写出半截目标文件。

**业务规则：**

- 警告不改变返回码的成功/失败语义；调用方选择是否把警告升级为失败。
- 取消是协作式的，不在任意机器指令处强杀线程。

#### F-010: 压缩包与 XML 安全限制

**用户故事：** 作为服务端开发者，我希望恶意压缩包和 XML 不能耗尽磁盘与内存，以便接口可以直接接收用户上传文件。

**验收标准：**

- [ ] Given 压缩比异常或解压后超过配置上限的 ZIP，When 打开，Then 在达到上限时失败，磁盘上不留下完整解压树。
- [ ] Given 含外部实体的 XML，When 解析，Then 不发起网络请求，不读取实体所指路径。
- [ ] Given ZIP 条目名为 `../` 开头，When 解包到临时目录，Then 路径被拒绝。

**业务规则：**

- 默认上限：解压后 2 GB、条目数 100 000、单条目压缩比 100。宿主可调低，不可在库内写死为无限制。
- HTML/MHTML 中的远程图片默认不下载。

#### F-011: 字体、整形与双向文本

**用户故事：** 作为业务用户，我希望中文、英文和阿拉伯文混排在 PDF 中顺序正确、字形不缺，以便打印件可读。

**验收标准：**

- [ ] Given 安装了 Noto Sans CJK 或思源宋体的环境，When 渲染含中文的 DOCX，Then PDF 文本抽取得到同一汉字序列。
- [ ] Given 文档指定了机器上不存在的字体，When 渲染，Then 使用配置的回退字体，并产生“字体替换”警告。
- [ ] Given 阿拉伯语句子，When 渲染，Then 视觉顺序为从右到左，抽取的逻辑顺序与原文一致。

#### F-101: 字处理文档创建与 OOXML 读写

**用户故事：** 作为集成开发者，我希望创建 DOCX 并读回已有 DOCX/DOCM/DOTX，以便生成合同和报告。

**验收标准：**

- [ ] Given 空文档并写入一段文字后保存为 DOCX，When 用 DocCore 再次打开，Then 得到一个段落且文字一致。
- [ ] Given 含自定义 XML 部件但无宏的 DOCX，When 打开再保存，Then 未识别部件按原样保留。
- [ ] Given DOCM，When 打开，Then 宏部件被保留且不被执行。

**业务规则：**

- P0 读写格式：DOCX、DOCM、DOTX、DOTM、Flat OPC。
- 未建模的 OOXML 部件默认按字节保留，除非保存选项明确选择丢弃。

#### F-102: 字符与段落格式、样式、列表

**用户故事：** 作为模板设计方，我希望标题样式、直接格式和多级列表在打开和导出后仍然生效，以便生成件符合公文模板。

**验收标准：**

- [ ] Given 段落使用“标题 1”，且样式指定加粗二号字，When 读取，Then 该段落的有效字体大小与加粗来自样式，而不是空的直接格式。
- [ ] Given 基于“标题 1”的自定义样式，When 修改父样式字号，Then 未覆盖字号的子样式跟随变化。
- [ ] Given 样式继承链成环，When 打开，Then 返回可诊断错误或打断环并警告，不无限递归。

**业务规则：**

- 有效格式的优先级：直接格式覆盖段落样式，段落样式覆盖文档默认。
- 样式 `basedOn` 深度上限 16。

#### F-103: 表格

**用户故事：** 作为集成开发者，我希望读写合并单元格和嵌套表，以便输出检验报告。

**验收标准：**

- [ ] Given 横向合并 3 列的表头，When 读取再保存，Then 合并范围不变，列网格一致。
- [ ] Given 单元格内再嵌一套表，When 导出 PDF，Then 内外表都可见且文本完整。
- [ ] Given 行跨页，When 排版，Then 行被拆分或整行移到下页的行为与表格属性中的“允许跨页断行”一致。

#### F-104: 节、页眉页脚与页码

**用户故事：** 作为业务用户，我希望不同节可以有不同纸张、页边距和页眉，页码连续或分节重计。

**验收标准：**

- [ ] Given 第二节改为横向 A4，When 导出 PDF，Then 第二节页面尺寸为横向，第一节保持纵向。
- [ ] Given 首页不同页眉，When 排版，Then 第 1 页与第 2 页页眉文本不同。
- [ ] Given 页码从 1 重新开始的节，When 更新页码域，Then 该节首页显示配置的起始页码。

#### F-105: 图片与形状

**用户故事：** 作为集成开发者，我希望插入 PNG/JPEG 并保留文档内已有浮动图片，以便报告含图。

**验收标准：**

- [ ] Given 插入一张 800×600 PNG，When 保存再打开，Then 图像字节可取出且尺寸不变。
- [ ] Given 环绕方式为四周型的浮动图，When 导出 PDF，Then 图与相邻文字不重叠，容差 2 pt。
- [ ] Given 损坏的图像部件，When 打开，Then 文档其余部分可读，该图位置产生警告。

#### F-106: 字处理分页排版

**用户故事：** 作为业务用户，我希望长文档分页、孤行控制、分页符和分节符生效，以便 PDF 页数与模板预期一致。

**验收标准：**

- [ ] Given 仅含普通段落的文档，When 连续排版两次，Then 分页位置一致。
- [ ] Given 段前分页，When 排版，Then 该段从新页开始。
- [ ] Given 显式分页符位于文档末尾且后面无内容，When 排版，Then 不额外产生空白内容页，除非节属性要求。

**业务规则：**

- 同一文档的排版结果在相同字体集、相同排版选项下必须稳定。
- 排版不修改源 DOM 中的文字，只生成 Layout IR。

#### F-107: 字处理导出

| XLSX | 否 | 是 | 否 | 是 | 是 | 否 | 是 | 是（按打印页） |
| PPTX | 否 | 否 | 是 | 是 | 否 | 否 | 否 | 是（按页） |
| PDF | 是（重建） | 是（重建） | 是（按页定位） | 是（重写/拆合） | 否 | 是（抽取） | 否 | 是（按页） |

“重建”表示产出可编辑对象，版式相对源 PDF 允许损失，具体容差见 F-310、F-311、F-312。P1 增加 EML/MSG 作为源，以及 QR、Code128 作为可嵌入图像。P2/P3 格式不进入上表。

#### F-902: CLI

**用户故事：** 作为批处理作业方，我希望不写 C++ 就能转换文件。

**验收标准：**

- [ ] Given `doccore convert in.docx out.pdf`，When 成功，Then 退出码为 0 且 out.pdf 可打开。
- [ ] Given `doccore convert in.pdf out.docx`、`out.xlsx` 或 `out.pptx`，When 输入是带文本层的 PDF，Then 退出码为 0，且输出能被 DocCore 再次打开。
- [ ] Given 失败，When 命令结束，Then 退出码非 0，stderr 含稳定错误码，stdout 不混入日志。

建议子命令：`detect`、`convert`、`merge-mail`、`recalc`、`extract-text`、`split-pdf`。

#### F-903: C ABI

**用户故事：** 作为其他语言的绑定作者，我希望用 C 接口完成打开、转换和关闭，并且错误由调用方释放。

**验收标准：**

- [ ] Given 通过 C ABI 打开后忘记关闭，When 在调试分配器下运行泄漏测试，Then 测试能指出该文档句柄。
- [ ] Given 任意 C ABI 调用，When 库内部抛出失败，Then 异常不穿越 C 边界，调用方得到错误码。

#### F-904: 本地 HTTP 服务

**用户故事：** 作为服务开发者，我希望用 HTTP 提交转换任务，以便脚本语言不必绑定原生库。

**验收标准：**

- [ ] Given 默认配置，When 服务启动，Then 只监听 127.0.0.1。
- [ ] Given 超过配置大小的上传，When 提交，Then 返回 413，不排版。
- [ ] Given 转换失败，When 响应，Then 正文为错误码 JSON，不返回部分结果文件。

**业务规则：**

- 服务无状态：文件只在请求生命周期内存在，结束后删除临时文件。
- 不提供公网账号体系；若绑定非本机地址，必须显式配置访问令牌。

#### F-905: 离线许可

**用户故事：** 作为许可管理员，我希望在无外网的机房启用 DocCore，到期后行为可预期。

**验收标准：**

- [ ] Given 有效许可文件，When 加载库，Then 全部已购买模块可用。
- [ ] Given 许可过期，When 调用转换，Then 返回许可错误，不改动输入文件。
- [ ] Given 开发模式，When 运行，Then 输出件带有不可关闭的“未许可”水印（PDF/PNG 直接绘制，DOCX/XLSX/PPTX 写入页眉或首行文字），且不用于冒充正式许可。

## 5. 数据需求

DocCore 处理的是用户文档，不是多租户业务库。SDK 模式不要求数据库。

**核心对象（逻辑上）**

- 字处理：文档、节、块（段落、表）、行内（文本轮、域、图）、样式、列表、页眉页脚
- 表格：工作簿、表、单元格、共享字符串、公式、定义名称、图表
- PDF：文档、页、内容流、字体、图像、大纲、注释
- 版式：页、层、绘制指令
- 任务（HTTP）：请求标识、输入输出的临时路径、状态、错误码。完成后删除

**数据量预估**

- 单文档设计上限：解压后 2 GB（可配置调低）
- 工作表：稀疏存储支持至少 100 万非空单元格的处理，超过则允许但需通过性能测试后才写入支持声明
- HTTP 临时盘：默认每请求最多 2 GB，进程级配额默认 8 GB

**保留策略**

- SDK 不保留文档副本
- CLI 只写调用方给出的输出路径
- HTTP 临时文件在请求结束时删除，进程崩溃后的清理在下次启动时按目录年龄删除（默认超过 24 小时）

## 6. 接口需求

### 6.1 宿主集成

| 项 | 规定 |
|----|------|
| 主接口 | C++20 头文件 |
| 稳定互操作层 | C ABI，错误码 + 显式释放 |
| 数据格式 | 输入输出为文档字节；配置为结构体或选项对象 |
| 认证 | SDK 无用户认证；许可文件在进程启动时加载 |

### 6.2 CLI

- 参数为子命令 + 标志，支持 `--help`
- 机器可读输出使用 `--json`
- 退出码固定为：0 成功；2 用法错误；3 格式或密码；4 许可；5 资源上限；6 取消；1 其他失败

错误码到退出码的映射（唯一映射表；C ABI 直接返回错误码，不做折算）：

| 错误码 | 名称 | CLI 退出码 |
|--------|------|------------|
| 0 | Ok | 0 |
| 1 | Unknown | 1 |
| 2 | InvalidArgument | 2 |
| 3 | Unsupported | 3 |
| 4 | NeedPassword | 3 |
| 5 | WrongPassword | 3 |
| 6 | Corrupt | 3 |
| 7 | Io | 1 |
| 8 | LimitExceeded | 5 |
| 9 | Cancelled | 6 |
| 10 | License | 4 |
| 11 | Formula | 1（CLI 转换中公式失败降级为警告，不单独占退出码） |

### 6.3 HTTP

- 协议：HTTP/1.1
- 默认绑定：`127.0.0.1:8080`
- 认证：仅当绑定非环回地址时强制 `Authorization: Bearer`
- 转换：`POST /v1/convert`，multipart 文件 + 字段 `target`（如 `pdf`）
- 响应：成功为文件流；失败为 JSON `{ "code", "message", "warnings" }`
- 不提供目录浏览和任意路径读取

### 6.4 外部系统

P0 不连接外部业务系统。字体来自操作系统字体目录和调用方追加的字体目录。OCR 插件在进程内加载，不默认调用云识别。

## 7. 约束与假设

**技术约束**

- 运行期不调用 Office、WPS、Acrobat 或 LibreOffice 进程
- 排版与公式结果由自有引擎产生
- 第三方代码必须许可证兼容商业发行，并随包列出
- 公开 API 不暴露第三方库的类型

**业务约束**

- 首个可交付版本只承诺 P0
- 功能对标的是公开能力清单，接受分阶段达到
- 客户文档不得作为改进模型被上传；默认识别与转换全部在进程内完成

**关键假设**

- 参考团队约 8 名研发加测试，用于第 8 节工期；人力变化时按比例调整
- 黄金样本由本项目自制、使用公有领域样本，或取得再分发许可
- 部署环境可以安装或随包提供至少一套可嵌入的中文字体（例如思源宋体）
- 调用方拥有待处理文档的合法使用权

**合规**

- 文件格式按公开规范独立实现
- 不反编译、不复制对标产品的二进制或源码
- 不把对标产品的名称用作 DocCore 的产品名、命名空间或包名。模块与命名空间使用中性词（text、sheet、pdf、deck），不与对标产品的模块名一一同构；对外文档只描述能力，不逐条对照对标模块。

## 9. 风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 分页与 Office 视觉差异 | 公文客户不接受 | 高 | 先锁定样本集与容差；差异写入已知问题，不在未复现时改算法 |
| PDF 转 Word/Excel/PPT 被理解成无损还原 | 验收争议 | 高 | 需求里分开写版式导出和有损重建；扫描件无文本层时失败或走 OCR，不产出空文档 |
| 公式兼容面过大 | 工期失控 | 高 | P0 只承诺列出的函数；其余返回明确错误 |
| PDF 解析器遇到畸形文件 | 安全或崩溃 | 中 | 模糊测试纳入 CI；解析器不使用不安全的对象图递归而不设深度上限 |
| 字体许可证 | 无法随包分发 | 中 | 默认使用系统字体；随包字体单独做许可证审查 |
| 旧二进制格式（DOC、XLS、MPP、PUB） | 投入大且只用在长尾 | 中 | 放到 M4/M5，首版用“转换前提示不支持” |
| 范围被理解成一次性对齐全部模块 | 无法交付 | 高 | 合同与发布说明只承诺当前里程碑的矩阵 |
| 第三方库许可证冲突 | 无法闭源发行 | 低 | 引入前评审；渲染后端若许可证不合适则换实现 |
| 宏被误认为会执行 | 安全事故 | 中 | API 命名用“导出宏项目/删除宏”，不提供 Run |
| 图表与条件格式不在 P0 | 含图表的 XLSX 导出 PDF 只见占位框，验收易被判不合格 | 高 | 合同与发布说明明确 P0 不含图表绘制；M2 末评估是否把 F-205 提前 |
| M2 工期 | 12 个月内交付 PDF 解析与三个重建器，是最高风险节点 | 高 | 门禁分级，先保证 PDF 读取与 PDF→DOCX，其余按 1.1 交付 |
| 模块命名与对标产品同构 | 商标与不正当竞争风险 | 中 | 模块与命名空间改用中性词，公开文档不做逐条对照 |

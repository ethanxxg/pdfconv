表 2：与 Aspose 的功能对比
能力维度	Aspose（商业引擎）	我们的 ownconv.py（完全自研）	完成度 / 差距
文本提取与字符保真	高，保留原字体/大小/颜色	高：基于 MuPDF 单词切分，间距、跨行连字符、CJK 均正确	~90%（差距在字体/颜色还原）
复杂版面（单/双栏、阅读顺序）	强	强：F/L/R 双栏识别 + 页眉页脚与正文分离	~90%
段落与标题层级	自动识别 Word 样式	基于字号/位置的 h1/h2/p/bullet/ref 分类	~80%（非常规标题可能误判）
表格（原生 Word 表格）	强，含合并/跨页单元格	find_tables()→原生表格，规整表格好；合并/跨页弱	~70%
图片 / 插图	提取原图	200dpi 裁剪 PNG 嵌入（位图 + 矢量簇）	~80%（矢量被栅格化）
数学公式	多为文本/图片（非可编辑 OMML）	同为文本或图片	~50%（与 Aspose 同级缺口）
字体 / 颜色 / 样式还原	高	低：统一 Times New Roman / Normal 样式	~30%
超链接 / 书签	支持	不支持	0%
页眉 / 页脚	保留为真正的页眉页脚	作为"期刊家具"有意过滤丢弃	~20%（属设计取舍，非能力缺口）
批注 / 注释	支持	不支持	0%
上标 / 下标	识别	基线偏移判据部分识别	~60%
扫描件 OCR	Aspose.PDF 内置 OCR	无	0%
矢量图形 / 流程图	部分保留矢量	栅格化为图片	~40%
处理速度	快（C++ 内核）	慢（Python + 逐图栅格化，论文含多图时尤慢）	较慢
中文 / CJK	支持	支持，已修复 CP1252 C1 控制字符问题	~90%
文本可编辑性（非图片）	文本可编辑	文本可编辑（表格/插图除外）	高
